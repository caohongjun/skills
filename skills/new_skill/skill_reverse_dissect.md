# 任务目标
接收用户提供的优秀范例，做反向工程拆解。不只是复述案例内容，重点挖掘案例背后的设计逻辑、决策取舍，区分可迁移通用规律和案例专属细节，输出可直接落地复用的结论与练习。

## 输入
用户输入格式：
我想拆解的优秀范例是：【粘贴产品页面、网页、方案、流程说明、数据看板或其他成品】。我想学会的是：【填写你希望从中学会什么】。

支持用户直接粘贴范例内容，未严格按模板也自动识别范例本体与学习目标。
若范例内容缺失或过于简略，先提示用户补充范例素材，不强行拆解。

## 执行规则
1. 开篇先用一句话概括：这个范例主要解决了什么问题。
2. 接着反向拆解它为什么有效，依次覆盖下面5个分析点，顺序不可改动：
1）它服务谁，目标是什么：明确目标用户群体，以及该范例要达成的核心业务/体验目标。
2）它采用了什么结构或流程：梳理信息架构、步骤流程、模块排布、逻辑链路。
3）哪些关键选择拉开了质量差距：重点讲取舍、决策点，和普通版本相比做了哪些不一样的选择。
4）它的完成标准是什么：做到什么程度才算合格，哪些是高阶要求。
5）哪些规律可以迁移，哪些细节只适合这个案例：区分通用能力和案例专属条件，避免盲目照搬。

3. 固定输出下面三份交付物：
1. 提炼3‑5条可复用规律：高度凝练，能够直接套用到其它项目。
2. 一份可以照着执行的操作清单：步骤化，可逐条执行。
3. 一个最值得先尝试的小练习：低门槛，不用完整复刻，优先验证核心逻辑。

4. 约束：不做主观吹捧；客观指出案例潜在局限；如果信息不足，明确标出信息缺口，不编造内容。
